# UI 状态与交互方案

本文件描述界面应如何解释**真实后台事件**。它不改变 Engine 或网页任务的执行规则。视觉规范见 [UI_DESIGN.md](UI_DESIGN.md)。

## 1. 全局与页面状态

全局至少维护：当前导航页、浏览器 Engine 是否运行、课程流程是否运行/暂停、作业/考试会话状态、待人工核验、最近错误。切页只改变可见页面，不发送 stop/cancel。导航运行标记从真实会话状态得出；回到页面时显示最近事件与上下文。

| 视觉状态 | 中央内容 | 保留的操作与说明 |
| --- | --- | --- |
| 空闲 `idle` | 作业链接输入区与主按钮 | 链接、模型配置校验；可进入历史与高级操作。 |
| 启动/等待 `opening`、`waiting` | 正在打开或等待网页/登录 | 显示真实等待原因；不能冒称正在识别或答题。 |
| 运行 `active` | 当前阶段大标题 + 小型步骤导航 | 仅展示真实可用的停止、暂停/恢复或浏览器控制。 |
| 人工待处理 `attention` | 当前阶段保留，突出核验/阻断原因 | 提供恢复浏览器等现有入口；重要提示持续显示。 |
| 停止 `stopped` | 原流程及已完成阶段保留 | 标记已停止，未返回的模型结果不得当作完成。 |
| 完成 `complete` | 极简完成图标、结果及下一步 | 不自动跳回启动页；自动提交关闭时不能声称已提交。 |
| 失败 `error` | 原上下文 + 可理解的失败原因 | 普通错误轻提示，重要错误页内持续，阻断性错误占中央并保留必要确认。 |

`blocked`、`unsupported`、`skipped`、`verification` 等不是统一的“失败”：要依事件含义保留可见原因和安全下一步。视频的 `paused`、`buffering`、`stalled`、`autoplay-blocked` 等使用视频页自己的状态文案。课程流程的 `course` 事件与作业 `homework` 事件可能同时出现；界面要标清当前是独立作业还是课程流程中的作业。

## 2. 作业阶段映射草案

当前 `HomeworkSession.emit()` 发送 `homework` 事件，包含 `state`、`message`，有时含 `question`、`answer` 等字段。实现时建立集中映射，缺失数据时显示保守文案，不靠计时器推算虚假进度。

| 后台事件示例 | 建议中央阶段/状态 | 说明 |
| --- | --- | --- |
| `opening`、`waiting` | 获取题目 / 等待网页 | 等待登录或开始作答时明确写等待。 |
| `recognizing`、`ready` | 识别解析 | `ready` 表示识别到题面，不等于任务完成。 |
| `thinking` | 模型求解或正在使用题目答案 | 当前代码可能使用题目自带答案，不能一律显示“模型求解”。需要结合事件消息或后续结构化来源字段。 |
| `filled` | 填写核对 | 填入答案不等于网站已接受提交。 |
| `submitting`、`submitted` | 填写提交 | 只有 `submitted` 才能表示本题提交已确认；不能把单题提交当作整份作业完成。 |
| `switching` | 获取下一题 | 连续任务按真实切题状态更新步骤。 |
| `complete` | 任务完成 | 依据当前作业任务结束事件，结果文案区分填写与确认提交。 |
| `stopped`、`error`、`blocked`、`unsupported` | 对应终止或待处理状态 | 保留最后阶段、题目和答案上下文。 |

`question`、`answer` 数据进入详情面板；答案默认优先可读结果，原始 JSON 仅深层查看。缺少结构化答案来源、阶段时间或总题数时不显示推测值。当前 `HomeworkPanel.render()` 直接显示事件消息与 JSON；重构时先保持相同数据路径，再调整呈现方式。

## 3. 关键交互

### 导航

- 正常侧栏：只显示图标与主标题；副标题默认不可见。鼠标移入该项时主标题缩小上移、副标题由下渐显；移出恢复，约 250ms，不触发页面跳动。点击才切页，悬停不切页。
- 折叠侧栏：只显示图标，悬停给名称提示。手动折叠与窄窗口自动折叠应可区分，以免窗口变宽时覆盖用户选择。
- 切页：任务保持运行；侧栏显示真实运行/注意标记，返回页面从保存的视图状态恢复。页面转场不等待后台命令。

### 输入与启动

- 空闲链接输入可粘贴、清空；历史记录只在有真实数据源时提供。无效或缺失链接时就地提示。开始按钮调用现有 `HomeworkPanel.open()` / 后续明确的任务动作，不改变登录、模型校验与保存顺序。
- “开始运行”是视觉主操作，但现有作业流程分“打开并登录”“识别”“单题解答”“连续填写”。实施时先明确主按钮对应哪一动作和何时需要人工登录；未确认前不可把多步行为合成无提示的一键自动提交。
- 自动提交与覆盖已有答案是现有可选设置。主画面文案、完成页与结果必须反映实际开关和网页确认结果。

### 详情面板

- 默认全收起；一次展开一个。打开其他入口时切换内容，关闭则恢复中央流程尺寸。
- 展开/收起只改变布局，不发后台命令。当前阶段始终可读；窄窗口详情内容独立滚动，操作按钮保持可达。
- 面板中的参数设置仅为任务快捷参数。涉及模型连接和密钥的保存/测试仍走原有 `HomeworkPanel` 逻辑；隐藏密钥值。

### 停止、完成、错误

- 作业 `homework_cancel`、课程 `course_stop`、视频 `stop`、考试 `exam_cancel` 是不同命令，按钮必须根据当前任务选对目标。暂停只在该任务已有能力时展示。
- 手动停止后保留流程和已确认阶段；完成后保留结果页；核验或提交结果不明确时保留页内提示及浏览器恢复入口。
- `App.poll()` 当前按约 150ms 取事件；视觉状态在事件到达的同一轮先更新，动画另用 `after()` 执行。新事件到来时取消或改向旧动画，不能让旧动画覆盖新状态。

## 4. 视图状态与业务状态的边界

共用详情过渡约 180ms，采用轻微位移与三次缓出；分组折叠使用相同节奏。打开、返回或快速反向切换只改变视图，不重建任务、不发送运行命令，保留输入和选中记录。视频启动后隐藏链接启动区，突出真实播放状态与时长；停止后恢复原链接。窗口关闭会取消待执行的 UI 回调。

UI 可以记住展开的面板、侧栏折叠、最近显示的阶段和页面，但不能把本地显示状态当作后台执行结果。不要因切换页面、窗口最小化、面板展开或动效结束而发送额外任务命令。日志、核验提示和停止确认按现有语义保留。真实后台事件不足以判断阶段时，显示事件原文或中性等待文案，并记录待补充的结构化事件需求。

## 5. 最小验收场景

1. 空闲页在宽、窄窗口与不同 DPI 下保持中央焦点；侧栏默认不显示副标题，悬停动画不移动其他项。
2. 任务启动、登录等待、识别、答案来源、填写、提交确认、切题均由真实事件切换；关闭自动提交时不宣称已提交。
3. 运行时切到视频、模型或记录页再返回，任务未中断且状态仍准确。
4. 展开四类详情时中央阶段仍可读，收起恢复；快速连续点击与新事件同时到来无闪烁或卡顿。
5. 作业停止、课程停止、视频停止、考试停止分别调用正确命令；已发出的模型请求结果不会在停止后显示为完成。
6. 完成、网页阻断、安全核验、提交结果不明和普通错误具有不同反馈，恢复浏览器入口可达。
7. 原有设置保存、密钥遮蔽、日志复制、做题记录、考试手动交卷提醒均可用。

## 6. 视频关闭恢复补充（2026-11-01 已实现）

视频停止时显示“正在关闭浏览器…”，确认结束后恢复原课程链接与“启动并登录”。浏览器已不存在时直接恢复；结束事件遗漏时，通过工作线程是否存活核对，不能只靠界面计时宣称已关闭。事件附带后台会话来源，旧会话迟到事件不得覆盖新会话状态。关闭等待期间不使用旧播放事件覆盖关闭提示。

停止信号立即交给后台，7 秒仍未完成时尝试结束已绑定的本助手浏览器进程；没有可用进程句柄时继续提示等待，不虚报成功。Tk 主线程不执行网页操作或等待进程退出。本次仅补充上述状态恢复，未改动导航、动画和页面布局。示例窗口在 Windows 150% 缩放下点击停止后已验证输入区和启动按钮恢复；其他 DPI 未在本次重新验证。
