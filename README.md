# 雨课堂学习助手

Windows 桌面应用。视频页支持二倍速、续播和最小化；“作业”页支持接入用户设置的模型，识别并填写当前作业的文本题目。

个人开发的非官方工具，与雨课堂平台运营方无隶属关系。当前为测试版，真实页面可能需要适配；首次识别与填写结果应由用户核对。

[Windows 测试包下载](https://github.com/wangribuzai9483-bot/yuketang-helper-public/releases) · [MIT 许可证](LICENSE) · [素材与第三方声明](THIRD_PARTY_NOTICES.md)

新版左侧导航包含课程流程、作业填写、视频播放、模型设置、运行日志、记录与经验和期末考试。各页底部的详情入口收纳配置和原有操作，打开、返回及分组折叠均采用统一的轻量动画。模型设置仍复用原来的密钥保存与连接测试逻辑；日志默认展示重要事件，完整日志在详情中查看。

Windows 默认使用 64px 暖白自定义标题栏，沿用系统窗口的最小化、最大化、还原和关闭流程。遇到窗口兼容问题，可在本目录终端运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -NativeTitlebar`，或设置环境变量 `YUKETANG_NATIVE_TITLEBAR=1` 后启动；无需重置配置或课程进度。其他系统以及标题栏安装失败时自动保留原生标题栏。

## 使用

1. 发布版：解压整个 ZIP 后双击 **雨课堂学习助手.exe**，不显示命令行，无需安装 Python。保留同目录 `_internal` 文件夹。源码版：双击 **启动雨课堂助手.cmd**，用于开发和依赖安装。
2. 点击 **启动并登录**，在打开的 Edge 窗口扫码或按学校要求登录。
3. 已填写 **课程直达地址** 时，程序使用该地址所属学校门户登录，并携带完整返回路径；登录后直接进入视频页。从课程首页或大纲页返回时也会补充跳转。没有直达地址时，程序识别课程卡片并尝试进入。
4. 默认二倍速、静音，并在视频真实播放结束后等待 5 秒，点击目录中下一条“视频”。
5. 点击 **最小化浏览器**，或勾选 **开始播放后最小化** 并点击 **应用设置**。用 **恢复浏览器** 显示窗口。
6. **暂停自动播放** 同时暂停视频；再次点击可恢复。**停止并关闭浏览器** 结束本次运行。

发布版默认使用本机已安装的 Microsoft Edge，也可以选择 Chrome。源码版需要带 Tcl/Tk 的 Python 3.10 或更新版本；首次双击启动脚本会建立本地环境并安装依赖，需要联网。

发布版的配置、密钥、浏览器状态与学习记录位于 `%LOCALAPPDATA%\YuketangHelper`；源码版仍使用本项目的配置和 `.runtime` 目录。两者不自动迁移个人数据。首次使用发布版需要填写自己的课程信息和模型设置，并重新登录网页。换新版程序时保留用户数据目录即可。

构建命令、私有 GitHub 上传范围和公开前事项见 [发布说明](docs/DISTRIBUTION.md)。

选择 Chromium 时，如尚未安装浏览器，先在本目录终端运行：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

界面的播放速度、静音、续播、自动最小化、暂停恢复选项都通过 **应用设置** 生效；修改浏览器、入口、目标课程或直达地址需停止后重启。更新程序代码后，应关闭整个旧助手窗口，再双击启动文件。

旧版本若停在 `about:blank`，并在 45 秒后提示“入口尚未加载完成”，本次已修复启动时的错误请求拦截。请关闭旧助手及其打开的浏览器后重新启动；登录目录与课程进度保留。后续连接失败时，日志会显示具体网络错误码或超时原因。

请填写自己的学校门户、课程名称和视频直达地址。视频页 `/ai-workspace/lms-graph/.../video/...` 和大纲页 `/v2/web/studentLog/...` 是不同入口，直达地址应优先填写视频页完整网址，保留 `is_chapter`、`node_id` 等参数。更换课程时请同时修改课程名和直达地址。

## 已实现的行为

- 使用本地独立浏览器目录保存登录会话，后续启动可复用仍有效的登录状态。
- 通过播放器自带倍速菜单设置速度，补齐 PC 播放器所需的鼠标进入和移动事件，更新播放器内部速度后再核对视频实际速度，避免其定时器恢复为 1 倍速。真正拒绝设置时停止反复修改，保留播放检查并显示实际速度。
- 识别源码中的 `.leaf-item` 课程目录，只续播标签为“视频”的项目，跳过作业、讨论、考试。
- 支持真实窗口最小化/恢复；界面持续显示播放时间、速度和状态。
- 识别常见可见弹窗后暂停并提示，处理弹窗后尝试继续；检测播放卡顿、视频加载失败、浏览器阻止自动播放和反复重置倍速。
- 限制意外暂停的连续恢复次数；若页面持续暂停，会提示恢复窗口检查。
- 同时打开多个同名课程页时，只控制其中一个。要切换受控标签页，可以关闭原受控页，或停止后重启。

## 统一课程流程

更新后关闭整个旧助手窗口，重新启动，在新增的 **课程流程** 页点击 **开始 / 继续课程流程**。

1. 目标课程、浏览器、倍速等沿用“视频播放”页配置；模型沿用“作业 → 模型设置”，启动统一流程时会保存当前模型设置。无需逐份填写作业地址。
2. 从网页当前选中的目录项开始，按目录顺序执行 **视频 → 普通作业 → 下一项**。相邻两项都是视频或都是作业时也会连续处理。进入作业后自动点击“开始作答”等入口，并定位第一题；逐题保留已有答案和提交记录，防止从网站记忆的中间题号漏做前面的题。
3. 如需作业处理后自动进入下一项，先在“作业填写”勾选 **填写后自动提交本题**。统一流程沿用该选项，等待每题提交成功后切题；整份作业到末尾才进入下一目录项。未开启时，填完本作业会暂停，等待你核对和手动提交，再点 **开始 / 继续课程流程**。在此时开启自动提交并继续，会先从第一题核对、提交已有草稿，再继续目录。
4. **暂停 / 恢复流程** 会同时控制课程切换和作业执行，保留尚未使用的模型结果；**停止课程流程** 会丢弃未填写的模型结果并停止后续切换，浏览器仍保留。手动打开、识别或解答作业，以及返回视频模式，会退出统一流程。
5. 支持后台最小化运行。检测到核验后先在后台自动处理，连续尝试失败才恢复浏览器并显示独立置顶提示，交由你手动完成；窗口消失后自动继续。真实网站的前台提示和自动续答问题已补充修复，状态见 `ROADMAP.md`，仍需在线复测。**恢复浏览器** 随时可手动把网页切回前台，不表示已经检测到核验。
6. 讨论、考试、未知类型、锁定内容、提交结果不明、目录变化或加载超时都会暂停，不会跳过去当作已完成。处理后可继续；需要跨过不支持的项目时，请手动选择后面的目录项，再点继续。

当前目录位置保存在本机 `.runtime/course-progress.json`，按课程地址、课程 ID 和课程名称隔离；重启后再次启动统一流程会优先回到上次位置。仅保存课程内容地址及必要目录参数，不保存登录凭据；页面记录仍决定是否已提交、已完成。视频播放进度由网站自己的记录恢复。

统一流程已通过临时浏览器的多视频、多作业连续处理测试；实际雨课堂下的目录入口、作业开始按钮及题号定位仍需结合在线页面复测。原有 **启动并登录** 仍只启用视频模式。

## 期末考试填写

在 **期末考试** 页填写自己的考试说明页地址。新安装不预填任何个人课程或考试链接。

1. 点击 **打开考试入口**，在助手浏览器登录并自行阅读考试说明、开始答题。程序绑定说明页及其打开的考试窗口；平台通常从 `/quiz/` 入口打开 `examination.xuetangx.com` 独立答题页。仅提供链接或停在说明页时，还没有可填写的题目。
2. 回到助手，输入题号后点击 **识别该题**。核对题干、题型和选项，再选 **解答并填写该题** 或 **从该题连续填写**。沿用“作业 → 模型设置”的 API、模型及密钥；支持判断、单选、多选、填空、简答及使用同一文本控件的论述题。
3. 也可在下方粘贴已有答案 JSON 后点击 **填入下方提供的答案**，不调用模型。选择题例如 `{"option_ids":["A","C"]}`；简答/论述例如 `{"text":"你的答案"}`；填空例如 `{"blank_answers":["第一空"]}`。选项编号以助手实际识别结果为准。
4. 默认保留已有答案；需要修改时显式勾选 **覆盖已有答案**。连续模式按当前已加载题目的顺序填写；题组未完全展开时会提示当前范围不完整，请在网页展开或切换后重新识别。停止按钮会丢弃未填入的模型结果。
5. 填写走正常控件事件，网页可能自动保存草稿；**最终交卷由用户在网页核对后操作**。身份核验、监考要求和未知弹窗由用户处理。检测到安全核验时提示并暂停，人工处理后继续原任务。普通课程流程仍在考试目录处暂停，不会自动开始考试。
6. 新填写内容存入 **记录与经验**，标为“期末考试 / 已填写”，不会仅凭填写就标记已交卷或已判对。无法识别时可导出考试页结构供适配。

当前依据平台公开考试组件的 `.exercise-item`、普通题型及 UEditor 控件适配，已经通过模拟五题试卷和临时 Edge 独立窗口测试。考试范围、时长与规则以用户实际网页为准。**尚未完成真实考试回归；真实题面的首次识别仍需核对**。图片、编程、材料子题和其他考试域名可能需要额外适配。

## 知识总结、做题记录与经验清单

更新后完全关闭旧助手再启动。顶层新增 **记录与经验** 页。

1. 在 **作业 → 模型设置** 选择 **作业结束后生成知识总结**，需要解题方法时再选择 **另外生成适用的做题技巧**，然后保存。两项默认关闭；知识性课程可只开知识总结。保存密钥或测试连接本身不触发复盘。
2. 更新后处理或重新读取的已答题会自动保存到本机，包括题干、选项、采用答案、来源、模型说明、作答/提交状态和历次变更。保存记录无需额外调用模型。**已做题记录** 支持搜索及查看历史；记录从本版本开始累积。
3. 连续模式在本份作业到达末尾后批量复盘；单题模式在填写完成后（开启自动提交时在提交确认后）复盘。沿用当前配置的接口、模型和加密密钥，额外消耗 API 额度。长作业分批处理，每批最多 20 题；相同内容和设置已经复盘成功时不自动重复调用。
4. 复盘独立在后台执行，课程可继续进入下一视频/作业。失败状态会保留在所选题目的“复盘任务记录”中；选择一条题目，再点击 **生成 / 重试所选作业复盘** 可以重试或重新生成。该按钮使用当前保存的模型配置，无需启动浏览器。
5. **经验清单** 按课程保存知识点、总结、可选技巧和来源题目。同一课程下同名知识点合并来源；在“个人修订 / 补充”编辑后点击 **保存修订**，再次生成会保留个人内容。可以删除所选经验，来源题目仍保留。
6. 网站明确显示“回答正确/回答错误/部分正确”时分别记录；其余为 **正确性待确认**。提交成功、题目自带答案及模型解释都不自动当作判分。不同学校的结果区域可能需进一步适配。

数据保存在 `.runtime/learning.sqlite3`，重启后保留；该文件包含题目、答案及个人修订。记录和复盘请求仅使用必要学习内容，密钥、Cookie、原始页面元数据不进入记录或模型提示。当前不自动将经验用于后续答题。

## 作业填写

更新后先关闭整个旧助手窗口，再双击启动文件。

1. 切换到 **作业 → 模型设置**，填写服务商提供的 **API Base URL**、**模型名称**、**API Key**，保存后点击 **测试连接**。使用兼容 Chat Completions 的接口；地址可填 `https://服务地址/v1` 或完整的 `/chat/completions` 地址。本机模型可用 HTTP localhost。
2. 切换到 **作业填写**，粘贴自己的普通作业链接，再点击 **打开作业并登录**。登录由用户在浏览器完成。必要时在网页点击“开始作答”。
3. 点击 **识别当前题**，检查助手显示的题干、题型和选项，再选择 **解答并填写当前题** 或 **连续填写本份作业**。
4. 连续模式逐题调用模型、填写并读取结果核对，等待 1.5 秒后点击题目导航栏的“下一题”。若网页弹出“刚刚答的习题还没有提交，需要提交吗？”，程序选择 **先不用了**，确认题目变化后再识别下一题，不选择“帮我提交”。默认保留已有答案和只读题，不跨到另一份作业。下一题按钮明确禁用时判定末尾；找不到按钮或出现未知弹窗时停止并提示。
5. 默认只填写答案。需要逐题提交时，在“作业填写”勾选 **填写后自动提交本题**，再点击单题或连续填写按钮。程序核对填写结果后提交当前题，等网页确认成功后再进入下一题；从当前题开始处理，不回到前面的题目。已有但尚未提交的草稿会保留内容并提交，已提交题默认跳过。如果网站弹出批量提交提示，只选择“仅提交本题”。提交失败或结果不明确时停止，不重复提交。模型的格式校验不代表答案一定正确。
6. **停止作业任务** 立即停止后续填写；已经发出的 API 请求返回后会被丢弃。网络请求自身可能持续到设置的超时，期间不会再发同一任务。**返回视频模式** 恢复视频流程。

多选题会逐项等待网页组件同步并重新读取控件，全部勾选完成后，再核对页面选项、组件中的当前草稿和模型返回的完整选项集合。任一处不一致时停止提交，避免连续点击导致前面的选择被覆盖。已通过多选、单选、多选混合连续作答，以及填写中人工核验后继续的本地测试；真实作业仍需复测。

### 选择题答案来源

“视频播放”页新增 **选择题答案来源**，写入 `config.json` 的 `answer_source`：

| 取值 | 行为 |
| --- | --- |
| `auto`（默认） | 题目数据里带正确答案（`content.Answer`）时直接使用，不再调用模型；没有自带答案或题型为填空/简答时照旧调用模型 |
| `model` | 一律调用模型，忽略题目自带答案 |
| `embedded` | 只用题目自带答案；遇到没有答案的题立即停止并提示，不会偷偷调用模型 |

- 读取位置：`homework.js` 从题面组件数据取 `content.Answer`，交给 `homework.py:_map_embedded` 归一化——支持选项编号（`B`）、序号（`1` 或 `0`）、选项文字（`乙`）和判断题的 `true/false`、`正确/错误`。映射不到选项时按设置回退或停止。
- 走“自带答案”时仍执行原有流程：填写 → 读取核对 → 可选的自动提交 → 核验处理 → 切题，只是不产生模型请求；界面日志会显示“本题使用题目自带的答案（未调用模型）”。
- 模型请求只包含 `type/stem/options/blank_count`，不会把自带答案发给模型。
- 若真实页面并不下发 `Answer`（不同学校/版本可能不同），`auto` 会自动回到模型，不需要改设置；`embedded` 模式则会明确报错提示。

短选项所在的宽行截图可能让 Windows OCR 返回空文本。现在会在空结果时自动裁掉四周空白，保留文字边缘后有限重试；使用实际失败的“柳宗元”截图验证能恢复识别。全空白图片仍会停止，不会跳过选项继续解答。


### 核验提示中的恢复浏览器

点击“恢复浏览器”时，先尝试直接恢复本助手启动的浏览器窗口，再由浏览器控制流程选中当前学习标签页。OCR 或页面读取尚在等待时，也可以先恢复窗口。原标签页失效会重新寻找仍有效的受控页面；不会通过重开页面丢失当前题目。

切回时提示窗会取消置顶，恢复失败或等待超过 5 秒会显示反馈。多次快速点击会合并，不累积反复切前台的操作。原生窗口定位只匹配本助手浏览器进程与已验证的窗口句柄，不随意选择其他 Edge/Chrome 窗口。

## 安全核验自动处理

实测到的“安全核验”主体是**点选路径**（“按住‘起’点，依次经过 1、2、3，最后到‘终’点松开”）。现场抓包确认：弹窗在作业 iframe 的**开放 Shadow DOM** 里，圆点和文字全部画在 `<canvas width=340 height=220>` 上，节点位置每次随机，DOM 与无障碍树都读不到字。另有少量 **拼图滑块**（腾讯 TCaptcha 跨域 iframe）。助手按层处理，全部在本机完成：

1. **降低触发概率**：浏览器以 `--disable-blink-features=AutomationControlled` 启动，并在页面脚本之前注入 `stealth.js`，补齐 `navigator.webdriver`、插件、语言、WebGL 厂商、`chrome.runtime`、通知权限等常见指纹差异。配置 `"stealth": true` 控制。
2. **画布作业（主路径）**：`bypass.js:readCanvas()` 直接 `getImageData` 读取画布像素 → 按饱和度连通域找出 5 个彩色圆点 → 以 24×24 归一化网格把每个圆点里的白色字形与**页面内实时渲染**的字形模板（1/2/3/4/5/起/终 × 5 字号 × 3 字体 × 粗细）做 IoU 匹配 → 得到“起 → 1 → 2 → 3 → 终”的顺序；`bypass.py:_canvas_path` 把画布坐标按 CSS 比例换算成页面坐标后连线。位置每次随机，每轮都重新读像素。
3. **DOM / 无障碍兜底**：若圆点是 DOM 元素（带底色的小圆），`bypass.js` 直接取字符节点；若落在封闭 Shadow DOM，用无障碍树（`Accessibility.getFullAXTree` + `DOM.getBoxModel` 等价路径）按名字取点；再不行才退回面板/整屏截图 + OCR + 彩色圆点匹配。
4. **拼图滑块**：`captcha.py` 用标准库解码截图 PNG，按列方向边缘能量和缺口内外亮度差定位缺口左边沿，再由 `bypass.py` 用 `page.mouse` 复现带加速、过冲、回退修正和纵向抖动的拖动曲线。
启动时不再注册网络拦截或替换校验响应。旧的 `shim` 响应替换功能已移除，其错误路由规则会阻塞普通登录页请求。

所有路径都以“核验标题消失”判定成功，失败则换新图重试（每次重绘都会重新识别，并重新获得一组尝试次数）。作业页和视频页都接入了检测：作业侧由 `homework.py` 的状态机在暂停作答前先尝试自动处理，视频/课程侧由 `engine.py` 每 3 秒在后台扫描一次，成功后不打扰你、不切换前台。全部失败时保持原行为：暂停任务、恢复浏览器、置顶提示等待手动完成，`核验完成后继续` 按钮照旧可用。每次识别与结果都追加到 `.runtime/verification.log`（`canvas-path` / `ocr-path` / `viewport-path` 等），首次遇到无法识别的结构会自动导出 `.runtime/verification-probe-*.json` 与截图。

配置项（写入 `config.json`，界面 **应用设置** 里的“自动处理安全核验”等价于 `solve` / `off`）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `verification_bypass` | `solve` | 界面使用 `solve` / `off`；兼容读取旧 `shim` / `both` 值，响应替换已移除 |
| `bypass_attempts` | `3` | 每次核验最多自动尝试次数（1–6），用完后转人工 |
| `bypass_slider_gain` | `0` | 滑块拖动比例，0 表示按轨道宽度自动计算；拖不到位时可微调 0.8–1.2（点选路径不使用） |
| `stealth` | `true` | 是否注入指纹一致性脚本 |

若真实页面结构与内置选择器不一致，点击 **课程流程 → 导出核验结构**，下次核验出现时会把各 frame 的节点树、尺寸和背景/滑块截图写入 `.runtime/verification-probe-*.json` 与同名 PNG。只记录布局信息，不含题面、Cookie 或图片内容以外的数据。

## 验证范围与使用提示

当前两个原始文本文件的 SHA-256 相同，实际是同一份**已进入课程的 DOM 快照**，其中有 33 个视频、29 个作业、2 个讨论、1 个考试。没有独立的登录页面、作业题面或真实弹题样本；视频签名链接也不能作为长期固定地址使用。因此程序操作登录后的真实播放器，而不直接播放快照内的视频地址。

本地测试覆盖了真实媒体二倍速、目录续播、弹窗暂停、卡顿/倍速重置提示和目标课程隔离。用户已反馈真实课程下二倍速、自动续播和后台播放正常。学习完成度以雨课堂页面显示为准；播放时间进度条表示本地视频播放位置。

作业功能参考了平台公开发布的题型组件，并通过本地模拟模型接口与真实 Chromium 控件验证。**本次修改尚未在用户登录后的作业页完成在线复测。** 自动化测试覆盖原有视频行为、用户导出页面结构的判断题填写、真实 Windows OCR、三题连续填写、核验暂停和恢复、逐题提交后等待网页确认、提交结果不明时不重复点击，以及密钥恢复；不能据此保证所有学校、版本或特殊题型都能识别。

若浏览器要求用户手势，请手动点击一次网页播放按钮。若学校页面在最小化后主动暂停，程序会尝试恢复，连续失败后提示处理。电脑休眠、网络中断或课程锁定也会影响播放。

视频弹题检测仍属于基础版本，弹题自动答题尚未实现。

“课程流程”页提供视频、作业按目录自动切换；单独使用视频模式时仍跳过作业，单独使用作业模式时仍限于当前本份作业。
